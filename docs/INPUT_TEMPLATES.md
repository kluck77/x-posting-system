# INPUT TEMPLATES

본 문서는 AI 호출 입력 포맷을 고정한다.
한 번 정한 틀을 흔들지 않는다.

---

## 1. 목적

- AI 호출마다 입력 형태가 흔들리면 출력도 흔들린다. 본 문서는 그 변동성을 끊는다.
- "기억해서 다시 만들기" 의 손실을 막는다. 매번 같은 구조로 입력한다.
- 누가 호출해도 같은 품질이 나오도록 입력 양식을 강제한다.

### 다른 문서와의 관계

- `docs/ACCOUNT_CONSTITUTION.md` : 무엇을 쓰는가 (주제 / 톤 / 금지)
- `docs/AI_ROLE_PROMPTS.md` : AI 가 어떤 역할로 응답하는가 (system prompt)
- `docs/WRITING_WORKFLOW.md` : 어떤 순서로 묶이는가 (단계)
- `docs/INPUT_TEMPLATES.md` (본 문서) : 그 단계에서 매번 무엇을 넣는가 (user message 양식)

위 4개는 한 묶음이다. 본 문서는 가장 현장에 가까운 마지막 한 장이다.

---

## 2. 공통 입력 규칙

모든 AI 호출 입력은 아래 8개 필드를 같은 순서로 채운다.

1. **제목** : 한 줄. 30자 이하. 낚시 금지.
2. **핵심 이슈** : 1~3 문장. 무엇이 일어났는지만.
3. **출처** : 1차 출처 URL 또는 기관 발표 명칭. 2차 보도면 명시.
4. **숫자/근거** : 핵심 숫자 3개 이내. 단위 포함. 비교 기준 시점 명시.
5. **해석 포인트** : 왜 지금 / 누구 / 자금흐름 / 심리 4축 중 사용할 축만.
6. **리스크 포인트** : 단정 금지 사항 / 반대 시나리오 / 모르는 부분.
7. **금지 포인트** : 이번 글에서 절대 쓰면 안 되는 표현 또는 결론.
8. **원하는 결과물 형식** : 길이 / 구조 / 톤 / 용도.

위 8개 중 하나라도 빠지면 호출하지 않는다.
빠진 채 호출하면 출력은 신뢰하지 않는다.

## 3. Grok 입력 템플릿

용도 : 실시간 시장 반응 / X 여론 / 짧은 히트 체크.

### 복붙용 템플릿

```
[역할] 너는 금융 시장 실시간 관찰자다.
[제목] 
[핵심 이슈] 
[출처] 
[숫자/근거] 
[해석 포인트] 
[리스크 포인트] 
[금지 포인트] 단정형 결론 / 가격 예측 / 매수 추천
[원하는 결과물]
- X 사용자들이 지금 이 사건에 어떻게 반응 중인지 3줄
- 반응의 온도 (과열 / 무관심 / 분열) 1줄
- 반응 중 사실 오인 가능성이 있는 부분 1줄
한국어로만. JSON 아님. 평문.
```

### 사용 예시

```
[역할] 너는 금융 시장 실시간 관찰자다.
[제목] 미 연준 12월 FOMC 의사록 — 추가 인하 지지 다수
[핵심 이슈] 12월 FOMC 의사록에서 다수 위원이 추가 인하 지지 의견을 냄.
[출처] FOMC Minutes 2026-01-03 공식본
[숫자/근거] 의사록 발표 직후 2년물 국채 금리 4.21% → 4.08% (-13bp, 30분 내)
[해석 포인트] 자금흐름 — 단기 채권 강세, 달러 약세
[리스크 포인트] 의사록은 시점 차 있음. 1월 CPI 가 다시 뒤집을 수 있음.
[금지 포인트] 단정형 결론 / 가격 예측 / 매수 추천
[원하는 결과물]
- X 사용자들이 지금 이 사건에 어떻게 반응 중인지 3줄
- 반응의 온도 (과열 / 무관심 / 분열) 1줄
- 반응 중 사실 오인 가능성이 있는 부분 1줄
한국어로만. JSON 아님. 평문.
```

## 4. Perplexity 입력 템플릿

용도 : 1차 출처 추적 / 사실 확인 / 인용 가능한 근거 수집.

### 복붙용 템플릿

```
[역할] 너는 1차 출처 검증자다.
[제목] 
[핵심 이슈] 
[알려진 출처] 
[검증할 주장]
- 주장 1 :
- 주장 2 :
- 주장 3 :
[원하는 결과물]
- 각 주장별로 1차 출처 URL 1개씩
- 출처가 1차가 아니면 1차를 찾을 때까지 거슬러 올라가기
- 1차 출처가 없는 주장은 "1차 출처 없음" 으로 표시
- 보고는 한국어 평문. URL 은 원문 그대로.
```

### 사용 예시

```
[역할] 너는 1차 출처 검증자다.
[제목] 미 비트코인 현물 ETF 1월 누적 순유입
[핵심 이슈] 1월 한 달간 미 비트코인 현물 ETF 누적 순유입이 신기록을 경신했다는 보도 다수.

[검증할 주장]
- 주장 1 : 1월 누적 순유입 60억 달러 돌파
- 주장 2 : IBIT 단독으로 25억 달러 차지
- 주장 3 : GBTC 는 같은 기간 순유출 유지
[원하는 결과물]
- 각 주장별로 1차 출처 URL 1개씩
- 출처가 1차가 아니면 1차를 찾을 때까지 거슬러 올라가기
- 1차 출처가 없는 주장은 "1차 출처 없음" 으로 표시

## 5. DraftWriter 입력 템플릿

용도 : 한국어 원문 초안 생성. 운영 라인 OpenAI gpt-4o-mini 호출.

### 복붙용 템플릿

```
[제목] 
[핵심 이슈] 
[출처] 
[숫자/근거] 
[해석 포인트] (4축 중 1~2개만)
- 왜 지금 / 누구 / 자금흐름 / 심리
[리스크 포인트] 
[금지 포인트] 단정 / 매수 추천 / 가짜 긴박감 / 번역투
[원하는 결과물]
- 길이 : 본문 4~6 문단
- 구조 : 사실 → 해석 → 시사점 3층
- 톤 : 냉정 / 날카로움 / 과장 없음
- 첫 문장 규칙 : 결론 또는 핵심 사실 1개로 시작
- 한 문단 한 주장
- 한국어 원문 (번역체 금지)
```

### 사용 예시

```
[제목] 한국 5대 은행 가계대출 잔액 7개월 만에 감소
[핵심 이슈] 1월 말 5대 시중은행 가계대출 잔액이 전월 대비 1.2조 원 감소.
[출처] 각 은행 2026-02-01 영업일 기준 자체 집계
[숫자/근거]
- 잔액 695.4조 원 → 694.2조 원 (-1.2조)
- 주담대 -0.4조 / 신용대출 -0.8조
- 7개월 만의 첫 감소
[해석 포인트]
- 왜 지금 : 가산금리 재인상 + DSR 강화 직후
- 자금흐름 : 신용대출 위축 폭이 더 큼
[리스크 포인트] 단월 데이터. 추세 단정 금지.
[금지 포인트] 단정 / 매수 추천 / 가짜 긴박감 / 번역투
[원하는 결과물]
- 길이 : 본문 4~6 문단
- 구조 : 사실 → 해석 → 시사점 3층
- 톤 : 냉정 / 날카로움 / 과장 없음
- 첫 문장 규칙 : 결론 또는 핵심 사실 1개로 시작
- 한 문단 한 주장
- 한국어 원문 (번역체 금지)
```

## 6. Reviewer 입력 템플릿

용도 : 초안 검수. 운영 라인 Anthropic Claude Sonnet 4 호출.

### 복붙용 템플릿

```

"""
(여기에 DraftWriter 결과물 본문을 그대로 붙임)
"""
[제목] 
[원본 출처] 
[원본 숫자/근거]

1. 사실 일치 — 본문의 모든 숫자/주장이 출처와 일치하는가
2. 해석 축 명시 — 왜 지금 / 누구 / 자금흐름 / 심리 중 어느 축인지 본문에서 식별 가능한가
3. 리스크 표현 — 단정형 / 가짜 긴박감 / 매수 추천이 있는가
4. 톤 — 냉정 / 과장 없음 / 번역체 없음
5. 첫 문장 — 결론 또는 핵심 사실 1개로 시작하는가
[원하는 결과물 — JSON 단일 객체. 코드 펜스 금지. 앞뒤 텍스트 금지.]
{
  "risk": "low | medium | high",
  "category": "fact | tone | structure | safety",
  "action": "approve | revise | reject",
  "reason": "한 문장",
  "fixed_body": "수정본 본문 또는 빈 문자열"

## 8. 좋은 입력 / 나쁜 입력 비교

### 비교 1 — 제목

- 나쁨 : `금리 어떻게 될까?`
  → 사건도 시점도 출처도 없음. 출력이 추측이 됨.
- 좋음 : `미 연준 12월 FOMC 의사록 — 추가 인하 지지 다수`
  → 사건 / 시점 / 출처 즉시 확정.

### 비교 2 — 숫자/근거

- 나쁨 : `비트코인 많이 올랐음`
  → 단위 / 비교 시점 / 출처 없음. 사실인지 검증 불가.
- 좋음 : `BTC 02-01 09:00 KST 기준 $96,200, 1주 전 대비 +8.4%`
  → 시점 / 단위 / 비교 기준 모두 명시. Reviewer 가 검증 가능.

### 비교 3 — 해석 포인트

- 나쁨 : `이거 호재인지 악재인지 알려줘`
  → AI 에게 단정을 요구. 본 시스템 금지 사항.
- 좋음 : `해석 축 — 자금흐름 / 단기 채권 강세 여부만`
  → 4축 중 하나로 좁힘. AI 가 그 축 안에서만 해석. 단정 강요 없음.

원칙 :
- 입력이 모호하면 출력은 거의 항상 더 모호해진다.
- 입력에서 미리 좁혀 놓지 않으면 사후 검수가 두 배 무거워진다.

## 9. 운영 메모

- 본 템플릿은 고정 틀이지 사고를 대신하지 않는다. 8개 필드를 채우는 사람이 여전히 중심이다.
- 본 문서와 `ACCOUNT_CONSTITUTION.md` 가 충돌하면 **`ACCOUNT_CONSTITUTION.md` 우선**. 계정 방향이 가장 위.
- 본 문서와 `AI_ROLE_PROMPTS.md` 가 충돌하면 **`AI_ROLE_PROMPTS.md` 우선**. 역할 정의가 입력 양식보다 위.
- 본 문서와 `WRITING_WORKFLOW.md` 가 충돌하면 **`WRITING_WORKFLOW.md` 우선**. 실제 작업 순서가 양식보다 위.
- 본 문서는 양식만 정한다. 양식이 워크플로를 끌고 가지 않는다.
- 새 AI 가 추가되면 본 문서에 새 섹션 1개만 추가한다. 기존 섹션 흔들지 않는다.
- 양식 자체가 흔들릴 만큼 잦은 갱신은 본 문서의 목적을 깬다. 갱신은 분기 단위로만.
