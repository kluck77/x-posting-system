# Operator Workflow — v8

실운영 기준 명령어 사용 가이드.
기능 설명이 아니라 "언제 쓰는지" 기준으로 정리.

---

## 명령어 사용 기준

### /draft `<url 또는 텍스트>`

**쓰는 상황:**
- URL이나 텍스트에서 바로 초안이 필요할 때 (분석 카드 없이 가장 빠른 경로)
- URL을 보내면 콘텐츠를 수집 후 즉시 파이프라인 실행
- 짧은 메모나 키워드를 넣으면 그대로 파이프라인 실행

**쓰지 않는 상황:**
- 분석 카드에서 모드(팩 / 댓글 / 스레드)를 선택해야 할 때 → URL을 그냥 전송

---

### /queue `<본문>` / /queue remove `<n>` / /queue clear

**쓰는 상황:**
- `/queue <본문>` — 지금 당장 게시하지 않고 최적 슬롯(오전 9시~오후 9시 KST)에 승인 알림을 받고 싶을 때
- `/queue` — 현재 대기 목록 확인 (🔔 마크 = 승인 알림 이미 발송됨)
- `/queue remove 2` — 2번 항목을 큐에서 제거
- `/queue clear` — 대기 중인 항목 전체 제거 (발행 완료 항목은 보존)

**쓰지 않는 상황:**
- 바로 초안 생성이 필요할 때 → `/draft` 쓸 것
- 큐 항목을 수정하고 싶을 때 → remove 후 새로 추가

---

### /monitor `[off|on|status]`

**쓰는 상황:**
- `/monitor off` — 휴가 중이거나 멘션 알림이 불필요할 때 멘션 모니터 일시정지
- `/monitor on` — 멘션 모니터 재개
- `/monitor` 또는 `/monitor status` — 현재 on/off 상태 확인

**동작:**
- off 상태는 재시작 후에도 유지됨 (data/monitor_state.json에 저장)
- 이미 off 상태에서 off 명령 → "이미 꺼져 있습니다" 메시지 (오류 아님)
- 이미 on 상태에서 on 명령 → "이미 켜져 있습니다" 메시지 (오류 아님)

---

### /status

**쓰는 상황:**
- AI 프로바이더 연결 상태 확인
- 멘션 모니터 on/off 상태 확인
- 게시 큐 대기 개수 확인
- 마지막 파이프라인 활동 시각 확인

---

### /note `<draft_id>` `<메모>`

**쓰는 상황:**
- 이번 draft에 한해 관찰한 것을 남길 때
- "이번 건은 각도가 이상했다", "BOK 뉴스치고 반응 평범했음" 같은 일회성 메모

**쓰지 않는 상황:**
- 앞으로도 계속 반영하고 싶은 스타일/각도 규칙 → `/hint` 쓸 것

**저장 위치:** `manual_notes` 컬럼에 평문 저장.  
DraftWriter에 주입되지만 `[HINT]`가 있으면 밀린다. fallback으로만 사용.

---

### /hint `<draft_id>` `<메모>`

**쓰는 상황:**
- 앞으로 매번 초안을 쓸 때 참고하게 하고 싶은 규칙이나 스타일이 생겼을 때
- 예: "항상 숫자를 첫 문장에 넣을 것", "BOK 관련 포스트는 생활 영향 각도로"
- `/perf`로 성과를 남겼는데, 이 스타일을 계속 쓰고 싶다고 판단될 때

**쓰지 않는 상황:**
- 단 한 번의 관찰 → `/note` 쓸 것
- 이미 /hints에 비슷한 힌트가 있을 때 → 먼저 확인하고 중복 방지

**저장 형식:** `[HINT] <메모>` 형태로 `manual_notes`에 저장.  
다음 초안 생성 시 DraftWriter prompt에 `[OPERATOR HINTS]` 블록으로 우선 주입.

---

### /hint clear `<draft_id>`

**쓰는 상황:**
- `/hints`에서 오래되거나 더 이상 유효하지 않은 힌트를 발견했을 때
- 특정 draft의 `[HINT]` 라인을 비활성화하고 싶을 때

**보존:** `[PERF]` 라인과 일반 메모는 지워지지 않는다.

---

### /hints

**쓰는 상황:**
- 현재 DraftWriter에 반영되고 있는 힌트 목록을 확인하고 싶을 때
- 매주 리포트 전에 열어보고 오래된 힌트를 정리할 때
- `/hint`를 새로 남기기 전에 중복 여부 확인할 때

---

### /perf `<draft_id>` `<메모>`

**쓰는 상황:**
- 포스트가 올라가고 48시간 내외에 반응(노출/좋아요/팔로워 변화 등)을 확인했을 때
- 성과가 있었든 없었든, 다음에 참고할 만하면 남긴다
- 예: "좋아요 30개 예상의 3배", "팔로워 +7, BOK 뉴스로는 최고", "반응 없음 — 주제가 너무 전문적"

**성과 후 추가 판단:**
- 이 스타일이 좋았다면 → `/hint <같은 draft_id> <스타일 규칙>` 도 남길 것
- 이 스타일을 반복할 이유가 없으면 → `/perf`만 남기고 끝

**쓰지 않는 상황:**
- 포스트 게시 전 → 게시 후에만 사용
- 매번 결과를 남길 의무는 없다. 특이점이 있을 때만

---

### /perf (인수 없음)

**쓰는 상황:**
- 최근에 `/perf`를 남긴 초안 목록을 빠르게 훑어볼 때
- 리포트 전 복기 용도

---

### /report

**쓰는 상황:**
- 주간 성과 리포트를 즉시 보고 싶을 때 (자동 발송은 월요일 9am KST)
- 볼 수 있는 것:
  - 7일 지표 (게시 수 / 승인률 등)
  - 성과 메모 요약: 카테고리/태그/형식 빈도 + 최근 메모 3개
  - 패턴 분석: 늘릴 후보 태그 / 줄일 후보 태그
  - 힌트 영향 요약: `[HINT]+[PERF]` 공존 건수 / 성과만 있는 건수 / 힌트만 있는 건수
  - AI 개선 포인트

---

## /note vs /hint 판단 기준

| 상황 | 명령 |
|------|------|
| "이번 draft만 보고 느낀 것" | `/note` |
| "다음 draft에도 계속 반영하고 싶다" | `/hint` |
| "좋은 성과가 나왔고, 이 스타일을 계속 쓰고 싶다" | `/perf` → `/hint` 둘 다 |
| "좋은 성과였지만 반복할 스타일은 아니다" | `/perf`만 |

---

## 주간 최소 루틴

매주 월요일 (WeeklyReporter 자동 발송과 같은 날):

1. **주간 리포트 확인** (`/report` 또는 자동 수신)
   - 성과 메모 요약에서 카테고리·태그 편향 확인
   - 힌트 영향 요약에서 "성과만 기록 (힌트 미변환)" 건 확인 → `/hint` 검토

2. **힌트 목록 점검** (`/hints`)
   - 오래되거나 상황이 바뀐 힌트 → `/hint clear`
   - 3개 이상 쌓였으면 실제 유효한 것만 유지

3. **이번 주 성과 기록**
   - 반응이 좋았거나 나빴던 포스트에 `/perf` 추가

이 세 가지가 이번 주 운영 기록 루틴의 전부다.

## 절대 하지 말아야 하는 사용 방식

- **`/hint`에 포스트 내용 초안을 통째로 넣는 것** — 힌트는 짧은 규칙/원칙이어야 한다. DraftWriter prompt에 그대로 들어간다.
- **`/note`와 `/hint`를 같은 draft에 혼용해서 같은 내용을 중복 저장** — 의도를 명확히 하고 하나만 쓸 것
- **`/perf`를 게시 전에 쓰는 것** — 성과 기록은 실제 반응을 보고 나서만
- **`/hint`를 매 draft마다 남기는 것** — 힌트는 "이 규칙을 매번 쓰겠다"는 의미다. 선택적으로
- **`/hint clear` 대신 `/note <id> 삭제`처럼 이상한 방식으로 무효화하려는 것** — `/hint clear <id>`만 사용
- **힌트가 DraftWriter에 반영됐는지 직접 확인하는 것** — 확인 불가. `[HINT]`가 있으면 자동 반영된다고 신뢰하면 된다

## 데이터 흐름 요약

```
포스트 게시
    ↓
반응 확인 (48h 이내)
    ↓
/perf <id> <반응 요약>
    ↓
이 스타일 계속 쓸 것인가?
  YES → /hint <id> <규칙>
  NO  → 끝
    ↓
다음 draft 생성 시 [OPERATOR HINTS] 자동 주입
    ↓
주간 /report에서 패턴 확인 → 힌트 정리 or 추가
```

## 명령어 빠른 참조

```
# 초안 생성
/draft https://뉴스URL
/draft 짧은 메모나 키워드

# 큐 관리
/queue                      ← 대기 목록 확인
/queue 포스트 본문 내용     ← 최적 슬롯용으로 등록
/queue remove 2             ← 2번 항목 제거
/queue clear                ← 대기 항목 전체 제거

# 모니터 제어
/monitor                    ← 현재 상태 확인
/monitor off                ← 멘션 알림 일시정지
/monitor on                 ← 멘션 알림 재개

# 시스템 상태
/status                     ← AI·큐·모니터·활동 요약

# 메모·힌트·성과
/note 42 이번 건 각도가 좁았음
/hint 42 BOK 뉴스는 생활 영향 각도로
/hint clear 42
/hints
/perf 42 좋아요 30개, 팔로워 +5
/perf
/report
```
